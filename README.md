# webcam-guard

**남는 USB 웹캠을 방 감시 카메라로 만드는 프로그램.** Windows 전용. 24시간 상시 녹화하고, 집 밖에서 휴대폰으로 실시간 화면과 지난 녹화를 본다.

Frigate·motionEye 같은 기성품 대신 직접 만들었다. 필요한 기능이 셋뿐인데 그것들은 Docker와 설정 파일을 요구했고, 무엇보다 **영상이 어디로 가는지 내가 알 수 있어야** 했다. 여기서는 녹화물이 네 PC의 폴더 밖으로 나가지 않는다.

```
ffmpeg 1개 프로세스 ──┬── clips/   10분짜리 mp4 아카이브
   (웹캠을 점유)      └── live/    HLS 실시간 스트림
                            │              │
                            │              └─> 움직임·얼굴 분석
                            ↓                        ↓
              guard.py (감시 · 자동삭제 · HTTP)   events/  로그북
                            ↑
                    휴대폰 브라우저
```

## 하는 일

- **24시간 상시 녹화** — 10분 단위 mp4로 쪼개 저장 (정전에도 마지막 10분만 손실)
- **휴대폰에서 실시간 보기** — 앱 설치 없이 브라우저만으로. 24시간 타임라인에서 원하는 시각을 눌러 재생
- **자동 삭제** — 설정한 기간·용량을 넘으면 오래된 것부터 지워서 디스크가 차지 않게
- **화면에 시각 표시** — 영상 자체에 시계가 찍혀서 나중에 언제인지 확실히 알 수 있음
- **로그북** — 움직임이나 얼굴이 잡힌 구간만 따로 적어둔다. 며칠치 영상에서 아무 일도 없던 시간을 건너뛰고 볼 곳만 바로 찾을 수 있음

## 일부러 안 하는 일

- **오디오 녹음** (`-an`으로 꺼둠) — 대화 녹음은 지역에 따라 법적 문제가 된다
- **알림** — 감지한 건 로그북에 적기만 하고 푸시는 안 보낸다. 오탐이 섞인 알림은 결국 꺼두게 되고, 그러면 알림도 로그북도 못 믿게 된다
- **누구인지 알아보는 얼굴 인식** — 얼굴이 "있다/없다"만 본다. 신원을 저장하면 이 프로그램이 다루는 데이터의 성격이 완전히 달라진다
- **클라우드 업로드** — 영상은 네 PC에만 있는다

## 설계 원칙

- **pip 패키지 0개.** 파이썬 표준 라이브러리와 ffmpeg 실행 파일만 쓴다. `python guard.py` 한 줄로 끝나야 하니까
- **서버는 파일 하나** (`guard.py`), **뷰어도 파일 하나** (`index.html`)
- **암호화 없는 HTTP.** 그래서 포트포워딩 대신 [Tailscale](#4-밖에서-휴대폰으로-보기--tailscale-권장)을 강하게 권한다

## 요구 사항

Windows 10/11 · Python 3.10+ · ffmpeg · USB 웹캠

## 빠른 시작

```powershell

python guard.py --list         # 2. 카메라 이름 확인

python guard.py                # 5. 실행
```

브라우저에서 `http://localhost:8088` (아이디 `admin`). 자세한 건 아래.

## 파일 구성

```
webcam-guard\
  ├─ guard.py                  ← 서버 (이 파일 하나가 전부)
  ├─ index.html                ← 휴대폰 뷰어
  ├─ .env.example              ← 복사해서 .env 로 쓴다 (비밀번호·카메라 이름)
  ├─ static\                   ← 뷰어가 쓰는 hls.js·폰트 (3-1 참고)
  ├─ start_guard.bat.example   ← 복사해서 자동 실행용으로 쓰는 템플릿
  ├─ README.md  PROJECT.md  CHANGELOG.md  CLAUDE.md
  └─ tools\                    ← 개발·검증용. 운영에는 필요 없음
```

`guard.py`와 `index.html`은 **같은 폴더**에 있어야 한다.

녹화물은 코드와 따로 `--root`(기본 `C:\CamRecordings`)에 쌓여:

```
C:\CamRecordings\
  ├─ clips\    10분짜리 mp4
  ├─ live\     실시간용 임시 파일 (계속 순환, 지워도 됨)
  └─ events\   로그북. 날짜별 파일, 하루 몇 KB
```

# 설치와 운영

여기서부터는 처음 설치할 때 순서대로 따라가면 되는 안내다.

## 1. ffmpeg 설치

PowerShell에서:

```powershell
winget install Gyan.FFmpeg
```

설치 후 PowerShell 창을 **새로 열고** `ffmpeg -version`이 나오는지 확인해.
(안 나오면 `--ffmpeg "C:\경로\ffmpeg.exe"` 옵션으로 직접 지정)

## 2. 카메라 이름 찾기

```powershell
python guard.py --list
```

출력에서 `[dshow @ ...] "HD Webcam"` 같은 줄의 **따옴표 안 이름**을 그대로 복사해.

> **Why 이름이 필요한가**: Windows는 웹캠을 DirectShow 장치명으로 식별해. 인덱스 번호는 USB를 다시 꽂으면 바뀌지만 이름은 고정이라 24시간 운영에 안전해.

## 3. 실행

`.env.example`을 복사해 **`.env`**로 저장하고 두 줄만 채워:

```ini
GUARD_PASSWORD=직접정한비밀번호
GUARD_DEVICE=HD Webcam
```

그리고 실행:

```powershell
python guard.py
```

브라우저에서 `http://localhost:8088` → 아이디 `admin`, 비밀번호는 위에서 정한 값.

> **Why `.env`인가**: 비밀번호를 `--password "..."`로 주면 명령줄 인자에 남는데, 이건 작업 관리자의 "명령줄" 열이나 `wmic process get commandline`으로 **같은 PC의 다른 프로그램에 그대로 보여.** PowerShell 기록에도 남고. `.env`는 파일에만 있고 `.gitignore`에 등록돼 있어서 실수로 커밋될 일도 없어.
>
> 참고로 `.env`를 읽는 데 `python-dotenv` 같은 패키지는 안 써. `KEY=값` 한 줄 파싱은 표준 라이브러리로 충분한데, 패키지를 하나 넣는 순간 "설치 명령 한 줄" 원칙이 깨지거든.

**설정 우선순위는 `명령줄 인자` > `환경변수(.env 포함)` > `기본값`.** 그래서 평소 값은 `.env`에 적어두고, 한 번만 다르게 쓰고 싶을 때 인자로 덮으면 돼:

```powershell
python guard.py --port 9000        # 이번만 9000번 포트로
```

`guard.py`의 모든 설정을 이렇게 쓸 수 있어. 이름 규칙은 앞에 `GUARD_`를 붙이고 대문자로 (`--retain-days` → `GUARD_RETAIN_DAYS`). 전체 목록은 `.env.example`에 있어.

### 3-1. 인터넷 없이 쓸 거라면 (권장)

```powershell
python tools/vendor.py
```

뷰어가 쓰는 hls.js와 폰트를 `static\` 폴더에 받아둬. **한 번만** 하면 돼.

> **Why 필요한가**: 이걸 안 하면 뷰어가 그 파일들을 인터넷 CDN에서 가져와. 감시 PC가 인터넷에 못 나가는 상황(회선 장애, Tailscale 전용 구성)에서 **안드로이드 크롬의 실시간 화면이 안 뜨는** 이유가 대부분 이거야. 받아두면 외부 요청이 0건이 돼. (안 받아도 CDN 폴백으로 동작은 해.)

### 주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--root` | `C:\CamRecordings` | 녹화 저장 폴더 |
| `--size` / `--fps` | `1280x720` / `15` | 해상도, 초당 프레임 |
| `--bitrate` | `1500k` | 화질(실측 **하루 15.4GB**). 용량은 이 값이 결정해 |
| `--max-gb` | `200` | 이 용량을 넘으면 오래된 것부터 삭제 (안전장치) |
| `--retain-days` | `10` | 이 일수가 지나면 삭제 (실제로 보관 기간을 정하는 값) |
| `--segment-seconds` | `600` | 파일 하나의 길이(10분) |
| `--port` | `8088` | 웹 뷰어 포트 |
| `--user` | `admin` | 뷰어 로그인 아이디 |
| `--channel` | `ROOM 01` | 뷰어 상단에 뜨는 이름. 카메라가 여러 대면 구분용 |
| `--no-timestamp` | — | 화면 속 시각 표시 끄기 |
| `--input-codec mjpeg` | — | 프레임이 낮거나 입력 실패할 때 |

로그북 관련 옵션은 [3-2](#3-2-로그북--움직임얼굴-기록)에 따로 있어. 전체 목록은 `.env.example` 아니면 `python guard.py --help`.

> **Why 10분 단위로 쪼개는가**: 24시간을 한 파일로 녹화하면 정전·강제종료 시 파일 전체가 깨져. 세그먼트 방식이면 마지막 10분만 손실돼. 특정 시각을 찾기도 쉬워.

> **Why `--max-gb`가 중요한가**: 720p 15fps로도 하루 15GB 이상 쌓여(실측 15.4GB). 자동 삭제가 없으면 며칠 만에 C드라이브가 꽉 차서 Windows 자체가 멈춰. 반드시 디스크 여유 공간보다 작게 잡아.

> **`--fps`를 낮춰도 용량은 안 줄어.** 파일 크기를 정하는 건 `--bitrate`야. 10fps로 낮춰도 1500k면 하루 용량은 거의 같고, 대신 같은 비트가 더 적은 프레임에 쓰이니 화질만 좋아져. 용량을 줄이려면 `--bitrate`를 낮춰. `--fps`는 CPU를 줄일 때 쓰는 옵션이야.

> **`--max-gb`와 `--retain-days`는 둘 중 먼저 걸리는 쪽이 이겨.** 기본값은 **10일 보관**에 맞춰져 있어. 하루 15.4GB × 10일 ≈ 154GB이고, `--max-gb 200`은 그보다 넉넉해서 평소엔 날짜 쪽이 먼저 걸려. 용량 쪽은 비트레이트가 튀는 등 예외 상황을 막는 안전장치야.
>
> 보관 기간을 늘리려면 **두 값을 같이** 올려야 해. 예를 들어 20일이면 `--retain-days 20 --max-gb 380`. `--retain-days`만 올리면 용량 상한에 먼저 걸려서 실제로는 안 늘어나.

## 3-2. 로그북 — 움직임·얼굴 기록

**장시간 켜두면 대부분의 시간은 아무 일도 없어.** 로그북은 뭔가 있었던 구간만 따로 적어둬서, 며칠치 영상을 처음부터 넘겨보지 않아도 되게 해줘.

기본으로 켜져 있고, 뷰어의 **기록** 탭에서 볼 수 있어:

- 24시간 막대가 **두 줄**로 나뉘어. 위는 녹화된 구간, 아래는 감지된 지점이야
- 아래 줄에서 **연한 건 움직임, 진한 건 얼굴**
- 목록이나 막대를 누르면 **그 시각으로 바로 이동**해서 재생돼

기록은 `C:\CamRecordings\events\2026-08-24.jsonl` 처럼 날짜별 파일로도 남아. 한 줄에 하나씩이라 메모장으로 열어봐도 되고, 필요하면 그대로 다른 도구에 넘겨도 돼:

```json
{"start": "10:39:12", "end": "10:39:48", "duration": 36, "kind": "face", "faces": 1, "score": 88.6}
```

### 감도 조절

방마다 조명·배경이 달라서 기본값이 항상 맞진 않아. 실제로 측정해서 정하는 게 확실해:

```powershell
python tools/calibrate.py
```

**두 번 돌려봐.** 방을 비우고 한 번(→ 전부 0에 가깝게 나와야 정상), 앞을 지나다니면서 한 번. 두 값 사이로 정하되 바닥 쪽에 가깝게:

```ini
GUARD_MOTION_THRESHOLD=1.0
```

카메라를 guard.py가 쓰는 중이면 녹화를 끄거나 `--from-live`로 돌리면 돼.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--no-logbook` | — | 로그북을 아예 끔 |
| `--motion-threshold` | `1.0` | 화면의 몇 %가 바뀌어야 움직임으로 볼지 |
| `--no-faces` | — | 얼굴 감지만 끔 (움직임은 계속 기록) |
| `--event-gap` | `10` | 몇 초 조용하면 한 사건이 끝난 걸로 볼지 |

> **Why 얼굴 감지에 OpenCV가 필요한가**: ffmpeg에는 얼굴 감지 기능이 없어(`dnn_detect` 필터는 별도 백엔드를 넣어 빌드해야 하는데 일반 배포판엔 없어). 그래서 OpenCV가 깔려 있으면 쓰고, **없으면 움직임만 기록하고 그대로 계속 돌아가.** guard.py 자체는 여전히 pip 패키지 없이 동작해. 얼굴 감지까지 원하면:
>
> ```powershell
> pip install opencv-python
> ```

> **Why 알림을 안 보내나**: 오탐이 섞인 알림은 며칠이면 무시하게 되고, 그때부터는 알림도 로그북도 안 믿게 돼. 적어두기만 하면 네가 필요할 때 확인하고, 틀린 항목이 있어도 그냥 넘기면 그만이야.

> **CPU는 얼마나 쓰나**: 실측으로 2초 세그먼트당 모션 50ms + 얼굴 78ms, 합쳐서 **코어 하나의 약 6%**야. 녹화용 인코딩이 이미 쓰는 양보다 훨씬 적어. 부담되면 `--no-faces`로 절반 이하로 줄어들어.

## 4. 밖에서 휴대폰으로 보기 — Tailscale 권장

**공유기 포트포워딩은 하지 마.** 이 서버는 HTTP(암호화 없음)라 비밀번호가 평문으로 지나가고, 인터넷에 열린 카메라는 실제로 스캐닝 봇에게 자주 털려.

대신 [Tailscale](https://tailscale.com) 무료 계정으로:

1. PC와 휴대폰 양쪽에 Tailscale 설치 → 같은 계정으로 로그인
2. PC의 Tailscale IP 확인 (`100.x.x.x` 형태)
3. 휴대폰 브라우저에서 `http://100.x.x.x:8088`

> **Why VPN 방식인가**: 두 기기만 있는 사설망을 만들어 주기 때문에 공유기 설정을 건드릴 필요가 없고, 외부에서는 포트 자체가 보이지 않아. 트래픽도 암호화돼.

같은 집 와이파이 안에서만 볼 거라면 그냥 PC의 내부 IP(`ipconfig`의 IPv4 주소)로 접속하면 되고, Windows 방화벽에서 해당 포트 인바운드 허용만 해주면 돼.

## 5. 부팅 시 자동 실행

`start_guard.bat.example`을 **복사해서 `start_guard.bat`으로 저장**하면 끝이야. 고칠 내용은 없어 — 카메라 이름과 비밀번호는 `.env`에서 읽으니까.

`Win+R` → `shell:startup` → 이 .bat 파일의 **바로가기**를 넣어두면 로그인 시 자동 실행돼.

> **뭐가 들었나**: guard.py 자체가 죽었을 때(파이썬 예외) 10초 뒤 다시 띄우는 루프가 있어. ffmpeg이 죽는 건 guard.py 안의 워치독이 이미 처리하고, guard.py가 죽으면 ffmpeg도 같이 정리돼.

> **Why 서비스가 아니라 시작프로그램인가**: 웹캠은 로그인한 사용자 세션에서만 접근돼. Windows 서비스로 등록하면 세션 0에서 돌아 카메라를 못 잡는 경우가 많아.

전원 설정에서 **절전 모드는 반드시 꺼둬** (제어판 → 전원 옵션 → 절전 안 함). 잠자면 녹화가 멈춰.

## 6. 알아둘 것

- **오디오는 일부러 녹음하지 않아.** 대화 녹음은 법적·프라이버시 문제가 생길 수 있어서 `-an`으로 꺼뒀어. 정말 필요하면 알아보고 켜.
- 실시간 화면은 HLS 방식이라 **3~6초 지연**이 있어. 이건 정상이고, 지연을 더 줄이려면 WebRTC가 필요한데 구조가 훨씬 복잡해져.
- `tools/vendor.py`를 돌려두면 뷰어가 외부 인터넷을 **전혀** 쓰지 않아. 안 돌렸다면 hls.js만 CDN에서 가져와(아이폰 Safari는 그것도 필요 없어).
- 카메라를 다른 앱(줌, 팀즈)이 쓰고 있으면 ffmpeg이 장치를 못 잡아. 상태창의 재시작 횟수가 계속 올라가면 이걸 의심해.
- **로그북 기록(`events/`)은 자동으로 안 지워져.** 하루에 몇 KB 수준이라 몇 년을 둬도 괜찮아. 다만 클립은 10일 뒤 사라지니까, 오래된 기록을 눌러도 영상이 없을 수 있어(뷰어가 "이 시각의 클립이 아직 없어"라고 알려줘).
- **영상 자체는 아무 데도 안 올라가.** 분석도 네 PC 안에서 끝나고, 로그북에는 시각·종류·지속시간만 남지 사진은 저장하지 않아.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `Could not run graph` / 입력 실패 | 다른 앱이 카메라 점유 중, 또는 `--size`를 카메라가 지원하지 않음 |
| **재시작 횟수만 계속 올라감** | 다른 앱(줌·팀즈)이 카메라를 쓰는 중인지 확인. 예전엔 고아 ffmpeg이 주원인이었지만 지금은 코드에서 막았어 |
| 프레임이 뚝뚝 끊김 | `--input-codec mjpeg` 추가, 또는 `--size 640x480` |
| `drawtext` 오류 | `--no-timestamp`로 실행 (폰트 경로 문제) |
| 실시간 화면만 안 나옴 (안드로이드) | `python tools/vendor.py`를 안 돌렸고 PC가 인터넷에 못 나가는 경우 |
| CPU 100% | `--preset`은 이미 veryfast — `--fps 10`, `--size 640x480`으로 낮춰. 로그북도 `--no-faces`로 절반 줄어 |
| **로그북이 계속 비어 있음** | 감도가 너무 둔한 것. `python tools/calibrate.py --from-live`로 실제 값을 보고 `GUARD_MOTION_THRESHOLD`를 낮춰 |
| **빈 방인데 기록이 잔뜩** | 반대로 너무 예민한 것. 화면에 TV·모니터·창밖 나뭇가지가 들어와 있는지 보고 임계값을 올려 |
| **얼굴이 하나도 안 잡힘** | OpenCV가 없는 상태야. 상태창의 `오늘 감지`에 `(모션)`이라고 뜨면 그 뜻이야. `pip install opencv-python` |
| 기동할 때마다 사건이 하나 생김 | 정상이야. 카메라 자동노출이 잡히는 첫 2초는 화면 전체가 변해 |

### 고아 ffmpeg (해결됨)

원래 이 프로그램에는 함정이 있었어. **작업 관리자로 강제 종료하면 ffmpeg만 살아남아** 카메라를 계속 붙잡고, 그 뒤엔 다시 켜도 카메라를 못 열어 재시작 카운터만 올라갔어.

지금은 Windows의 Job Object에 ffmpeg을 묶어놔서 **guard.py가 어떤 식으로 죽든 ffmpeg도 같이 정리돼.** 강제 종료로 실제 확인했어. 어떻게 꺼도 괜찮아.

혹시 예전 버전으로 돌린 흔적이 남아 증상이 보이면 한 번만:

```powershell
taskkill /F /IM ffmpeg.exe
```
